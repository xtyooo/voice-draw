# AI 语音绘图工具设计文档

## 1. 赛题理解

本项目围绕「AI 语音绘图工具」开发，目标不是生成一张不可编辑的图片，而是做一个只靠语音完成创作的矢量绘图工具。用户不能使用鼠标或键盘来画图、选图或改图，只能通过语音说出需求，系统把语音转成文字，再把文字拆成标准绘图命令，最后由画布执行。

赛题重点有三点：第一点，语音指令要能准确理解，并且在说法不完整或对象有歧义时给出容错反馈；第二点，语音到绘图操作的链路要尽量短，简单指令不能每次都依赖大模型；第三点，复杂指令要能拆成多个步骤，例如一句话生成流程图，或者一句话连续创建图形、连接图形、修改图形。

## 2. 系统方案

VoiceDraw 采用前端优先的架构，画布内核使用 Excalidraw，语音识别使用 `react-speech-recognition` 封装的浏览器 Web Speech API，复杂流程图解析通过本地 Node 服务调用 OpenAI 兼容接口。

```text
用户语音
  -> ASR 语音识别
  -> 文字指令
  -> 文本归一化
  -> 本地规则解析 / AI 解析
  -> 标准绘图命令
  -> 命令校验和对象解析
  -> Excalidraw 画布执行
  -> 文字反馈、Toast 反馈、执行记录
```

AI 不直接控制画布，它只负责把复杂自然语言转成 JSON 或 Mermaid，真正的绘图操作由 `CanvasAdapter` 执行，这样能减少误操作，也方便测试和回滚。

## 3. ASR 设计

当前版本已经接入 ASR，具体实现是 `react-speech-recognition + Web Speech API`，代码位于 `src/voice/useVoiceInput.ts` 和 `src/voice/speechConfig.ts`。系统使用 `zh-CN` 作为识别语言，开启连续识别，识别到文本后会在短暂停顿后自动执行，不再要求用户点击「执行」按钮。

暂时不单独接入云厂商 ASR 或本地 Whisper，原因有三个：一是浏览器 Web Speech API 已经能满足比赛现场的基础语音输入，接入成本低，演示链路短；二是赛题更关注语音指令如何变成绘图操作，而不是 ASR 模型本身；三是外部 ASR 会增加密钥、计费、网络延迟和现场稳定性风险。

后续如果要增强，可以加一个可选 ASR 层：浏览器支持 Web Speech API 时走浏览器识别，不支持或识别质量差时，把音频上传到后端，由 Whisper、七牛云或其他云 ASR 服务转写，再进入同一套命令解析管线。

## 4. 计划支持的指令能力

计划支持的能力分为五类。

一是基础创建：画圆形、矩形、菱形、文字，支持颜色、大小和位置描述。

二是对象编辑：选中刚才的图形、按颜色或文字选中对象、移动、放大、缩小、改颜色、删除。

三是连接和流程：从一个对象连到另一个对象，用箭头表达关系，一句话生成登录、注册、订单支付等流程图。

四是画布控制：撤销、重做、清空画布、导出 PNG。

五是容错确认：找不到对象时给出原因，找到多个对象时要求用户继续说「左边那个」「第二个」或「取消」。

## 5. 已实现能力

当前版本已实现基础语音绘图、对象记忆、二次确认、复杂流程图生成和多步骤本地指令拆解。

本地规则可以解析这些指令：`画一个红色圆形`、`画一个蓝色矩形`、`在中间写“用户登录”`、`画一条从圆形到矩形的箭头`、`把刚才的矩形放大一点`、`选中蓝色的节点`、`把它往右移动一点`、`删除左边的红色圆形`、`撤销上一步`、`清空画布`、`导出图片`。

复杂指令支持两条路径：常见流程图可以本地生成 Mermaid，例如登录、注册、订单支付流程；更开放的流程图需求会走 `/api/ai/parse`，由服务端调用 OpenAI 兼容接口，前端只接收结构化结果，不暴露 API key。

系统已经移除手动绘图输入框、快捷执行按钮和候选点击按钮，绘图和确认都必须通过语音完成。示例指令只作为文字提示展示，不能点击执行。

## 6. 复杂指令拆解

简单命令直接走本地规则，响应更快，也不产生 AI 成本；包含多个动作的本地指令会先按「然后、接着、之后、再、并且」拆成多个步骤，再逐条校验和执行。

例如用户说：

```text
画一个红色圆形，然后画一个蓝色矩形，再画一条从圆形到矩形的箭头
```

系统会拆成 3 个命令：创建红色圆形、创建蓝色矩形、创建箭头。执行器会先执行第一步并更新对象记忆，再执行第二步，最后连接两个对象，这样后续步骤可以引用前面刚创建的图形。

## 7. 准确性与容错

系统用 `SceneMemory` 维护画布对象索引，记录对象 ID、形状、颜色、文字、位置、创建时间和别名。用户说「刚才那个」「它」「蓝色节点」「文字是登录的框」时，系统会在对象索引里解析目标。

如果目标不存在，系统不会执行危险操作，会反馈「没有找到对应对象」。如果找到多个候选，例如画布上有两个红色圆形，系统会进入语音确认状态，提示用户继续说「第一个」「左边那个」「右边那个」或「取消」，只有确认后才会删除或修改。

## 8. 响应延迟设计

为了降低延迟，系统把简单命令放在本地解析器里处理，不经过后端和大模型。语音识别得到文本后，前端等待约 650 ms 的停顿时间，避免一句话还没说完就执行；一旦文本稳定，就自动进入解析和执行流程。

复杂流程图才调用 AI 服务，调用时只发送用户文字和简短画布摘要，不发送截图，也不上传完整画布文件。这样可以降低网络传输量、调用成本和隐私风险。

## 9. 未完成部分与原因

本地 Whisper 或云厂商 ASR 尚未接入，原因是当前 Web Speech API 已能完成语音到文字的基本链路，赛题交付重点更需要优先保证绘图命令闭环、复杂指令拆解和容错确认。后续可以把 ASR 抽成统一接口，再增加 Whisper 或云 ASR 作为备选。

自动排版能力只覆盖流程图生成和基础自动摆放，还没有做完整的「整理画布」「对齐所有节点」「平均分布」等高级排版指令，原因是这些能力需要更复杂的布局算法和更多交互测试。

语音播报反馈尚未实现，当前反馈方式是文字状态、执行记录和 Excalidraw Toast，原因是浏览器语音播报会和麦克风输入互相影响，比赛演示优先保持识别稳定。

多人协作、模板库、思维导图和时序图暂未实现，原因是这些属于扩展场景，当前版本先保证绘图、编辑、确认、流程图生成和导出这些核心能力。

## 10. 验证方式

项目包含命令解析、对象记忆、确认逻辑、自动执行和多步骤执行的单元测试。提交前使用以下命令验证：

```powershell
npm run test
npm run lint
npm run build
```

演示时建议使用 Chromium 内核浏览器打开 `http://127.0.0.1:5177`，先授权麦克风，再按 `docs/demo-script.md` 中的脚本进行展示。
